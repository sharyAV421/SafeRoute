# HU-02 — Gestión de roles y permisos

**Código y título:** HU-02 — Gestión de roles y permisos  
**Como:** Administrador  
**Quiero:** administrar los roles asignados a usuarios  
**Para:** que cada actor acceda a las funciones previstas para su responsabilidad.  
**Actor:** Administrador. **Prioridad:** Alta (propuesta).

## Validación INVEST

Independiente: Sí. Negociable: Sí, permisos por módulo requieren acordarse. Valiosa: Sí, sustenta la separación de actores. Estimable: Parcialmente. Pequeña: Sí. Comprobable: Parcialmente, faltan permisos detallados de RF-02.

## Criterios de aceptación (Gherkin)

```gherkin
Característica: Gestión de roles
  Escenario: Consultar roles disponibles
    Dado que el Administrador tiene acceso a la gestión de usuarios
    Cuando consulta los roles
    Entonces SafeRoute muestra los roles definidos en el sistema
  Escenario: Intento de acceso sin autorización
    Dado que un actor no tiene permiso para administrar roles
    Cuando intenta realizar una operación de administración
    Entonces SafeRoute rechaza la operación
```

## Supuestos y reglas de negocio

- El modelo muestra enum Rol con ADMINISTRADOR, RESPONSABLE_EMERGENCIAS y USUARIO_EVACUADO. Se toma como catálogo del UML.
- No están definidos permisos granulares, creación de roles personalizados ni asignación múltiple; no se presuponen.

**RF:** RF-02 (título: “Gestión de roles y permisos”). **Componentes:** Gestión de usuarios; UsuarioController/Service/Repository; Usuario y Rol. **Mockup:** M02 en `../mockups/html/02-roles.html`.
