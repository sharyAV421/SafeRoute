# HU-01 — Inicio de sesión

**Código y título:** HU-01 — Inicio de sesión  
**Como:** usuario registrado de SafeRoute  
**Quiero:** iniciar sesión con mis credenciales  
**Para:** acceder a las funciones correspondientes a mi rol.  
**Actor:** Administrador, Responsable de emergencias o Usuario evacuado.  
**Prioridad:** Alta (propuesta; la prioridad RF no fue adjuntada).

## Validación INVEST

Independiente: Sí, el acceso precede a los módulos. Negociable: Sí, el detalle de autenticación requiere definición. Valiosa: Sí, habilita el uso por rol. Estimable: Parcialmente, faltan reglas de credenciales y sesión. Pequeña: Sí. Comprobable: Parcialmente, a validar con RF-01 completo.

## Criterios de aceptación (Gherkin)

```gherkin
Característica: Inicio de sesión
  Escenario: Acceso con credenciales válidas
    Dado que existe una cuenta habilitada
    Cuando el usuario envía sus credenciales válidas
    Entonces SafeRoute confirma el acceso y presenta las funciones de su rol
  Escenario: Credenciales no válidas
    Dado que el usuario está en la pantalla de acceso
    Cuando envía credenciales que no corresponden a una cuenta habilitada
    Entonces SafeRoute informa que no fue posible iniciar sesión
    Y no presenta funciones protegidas
```

## Supuestos y reglas de negocio

- El UML confirma autenticación y roles, pero no define formato de credenciales, recuperación de contraseña, expiración ni bloqueo por intentos. Se dejan pendientes.
- El rechazo debe ser genérico; el texto y política de sesión requieren confirmación.

**RF:** RF-01 (título disponible: “Inicio de sesión”). **Componentes:** Gestión de usuarios; UsuarioController → UsuarioService → UsuarioRepository; entidad Usuario y enum Rol. **Mockup:** M01 en `../mockups/html/01-acceso.html`.
